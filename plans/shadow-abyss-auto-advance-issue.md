# ShadowAbyss（神曲）问题记录：没有选项也要点击

> 状态：**只记录，待单独立项**（2026-11-09 用户决定）。修复方向依赖 `plans/painted-skin-plan.md` 落地的 `_engine/story.js`。

## 现象

剧情是单线、没有真正选项的时候，玩家仍然必须点击才能推进。

## 量化（按游戏内置的自动选择策略，走真结局路线模拟）

| 项目 | 数量 |
|---|---|
| 经过节点 | 55 |
| 玩家总点击 | 267 |
| 其中真正的抉择（≥2 个选项） | 8 |
| 只有一个选项、却要点的按钮 | 45 |
| 每句台词翻页 + 章节卡 + 条件路由的「继续」 | 约 214 |
| 全剧（66 个节点）中单选项节点 | 49 / 58 个带选项的节点 |
| 单选项上挂着数值、旗标或成就 | 33 个 |

267 次点击里约 97% 不是决定。

## 根因（两层）

1. **剧本格式**：`story/divine-comedy.json`（来自 storyToGame）要求每个节点以 `choices` 结尾，单线推进只能写成单选项。而且其中 33 个单选项挂着 `changes`，不能直接删。
2. **运行时**：`game/systems/runtime.js` 的 `_advance()` 让每句台词打完字后等待输入；`routes` 和章节卡也走 `_renderContinue` 等点击。

## 修复方向（立项时执行）

- 迁移到 `_engine/story.js`（画皮落地的自动播放运行时，条件和效果语义与神曲兼容）。
- 剧本转换规则：单选项的文字改为主角的一句台词；`changes` 改为节点的 `onEnter`；`next` 并入节点的 `next`。转换后用格式检查保证不再有单选项。
- 不改游戏内容。验证沿用 `scratch/verify_shadowabyss_story.mjs`（真结局可达），再加一条「60 秒无输入也持续推进」的断言。
- storyToGame 生成器本身也会产生单选项，需要同步修改（另一个仓库）。
