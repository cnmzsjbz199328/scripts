# 横版推进游戏架构蓝图（魂斗罗式 side-scroller）

> 本文档是**给下一个新游戏用的技术蓝图**，不是对现有游戏的改造指南。
> 项目现有游戏（以 **ShadowForge** 为代表）多为「单屏竞技场」骨架：固定一屏、
> 计时器刷波、清完切场景。这是一种成立的玩法（读招、锁场 Boss 战都靠它），保留不动。
> 本文描述另一种骨架——**横版推进**：角色一路前进，摄像机跟随，场景连续滚动变化，
> 敌人随推进出现。两类骨架各有优势，按题材选用。

---

## 0. 两类关卡骨架对比（选型依据）

| | 单屏竞技场（ShadowForge 型） | 横版推进（本文档） |
|---|---|---|
| 世界 | 世界 = 一屏（960×540），玩家 x 钳制在屏内 | 世界远宽于屏（每段 3000~4000px），屏幕是滑动窗口 |
| 摄像机 | 不动（只有 shake） | 跟随玩家，可加棘轮（只进不退） |
| 场景变化 | 清波后原地交叉渐变换背景图 | 走出来的：背景随推进连续滚动，交界处过渡带 |
| 刷怪驱动 | 计时器（`{ t: 1400, type, x }`） | 推进距离（`{ at: 2400, type, dx }`） |
| 强项 | 读招格斗、波次压力设计、Boss 1v1 | 探索感、节奏张弛（赶路↔遭遇战）、场景叙事 |
| 适用题材 | 竞技场格斗、塔防、守点 | 动作闯关、跑酷战斗、公路/旅途叙事 |

两者**不互斥**：横版推进游戏在关键节点用「锁点」把镜头锁成单屏，
锁点内部就是一个完整的竞技场波次战——竞技场骨架的全部积累（读招、预警环、
波次控制）在锁点里原样复用。

---

## 1. 沿用的项目约定（不重复造轮子）

以下全部照 `MIGRATION.md` 执行，横版游戏无特殊：

- 目录结构：`<Game>/game/{config,levels,systems/,scenes/,main}.js`，按序 `<script>` + 命名空间全局。
- 共享层：`_engine/{hud,audio,morph,pointcloud}.js`。
- 设计原则「即开即玩」：❌ 存档 ❌ 关卡选择 ❌ 星级；✅ START 直进第 1 段、线性通关、R 重开、M 静音。
- 对外契约：`window.__probe()` / `window.__gameState.player` / `?autostart` / `navigator.webdriver` bot。
- 素材管线：game-gen 的 panorama → material/char/object 派生流程。

## 2. 核心：世界坐标 + 摄像机

### 2.1 世界定义

```js
// config.js
NS.WORLD = {
  W: 18000,            // 世界总宽 = 各段之和（5 段 × ~3400 + 过渡带）
  H: 540,              // 高度仍是一屏（纯横向推进，不做纵向卷轴）
  FEET_Y: 452,         // 地面基线，同竞技场约定
};
```

### 2.2 摄像机装配（Phaser 3）

```js
// create()
this.cameras.main.setBounds(0, 0, NS.WORLD.W, NS.WORLD.H);
this.cameras.main.startFollow(this.player, true, 0.12, 0);  // 横向平滑跟随
this.cameras.main.setFollowOffset(-Forge.W * 0.18, 0);      // 玩家偏左 1/3，视野留给前方
```

- **跟随点偏前**：玩家在画面左 1/3 处，前进方向多留视野（魂斗罗惯例）。
- **棘轮（可选，推荐）**：推进后不许回卷。维护 `this.camMinX = max(camMinX, cam.scrollX)`，
  每帧 `cam.scrollX = max(cam.scrollX, camMinX)`，玩家 x 钳到 `[cam.scrollX + 40, cam.scrollX + W - 40]`。
  棘轮让「向前」成为唯一方向，杂兵不清也能跑过去，节奏归玩家掌控。
- **锁点时**：`cam.setBounds(lockX, 0, Forge.W, H)` 收紧成单屏 + 停止 follow；
  解锁后恢复世界 bounds 并重新 follow。

### 2.3 屏幕空间 vs 世界空间（最容易踩的坑）

镜头一动，所有「画在固定坐标上」的东西都会被甩在身后。装配时必须分两类：

| 世界空间（跟世界走） | 屏幕空间（钉在屏上，`setScrollFactor(0)`） |
|---|---|
| 玩家、敌人、投射物、减速带等地面效果 | 暗角 vignette、叙事卡 toast、提示文字 |
| 地面带、中景装饰物 | HUD（本就是 DOM，天然屏幕空间） |
| 视差层（scrollFactor 0.2~0.6，见 §3） | 全屏色调滤镜、reduced-motion 遮罩 |

前景氛围雾建议折中：`scrollFactor(0.9)` 左右，既有跟随感又不完全钉死。

## 3. 背景：视差长卷

### 3.1 分层结构

```
远景  scrollFactor 0.25   地平线/天空/远山 —— tileSprite，横向无缝平铺
中景  scrollFactor 0.55   建筑/树木剪影 —— tileSprite 或按段摆放的大件
地面  scrollFactor 1.0    地脊带 —— 程序生成时按世界宽度分 chunk 平铺
前景  scrollFactor 1.0+   偶发遮挡剪影（柱/枝），制造纵深
```

`tileSprite` 用法：创建为一屏大小 + `setScrollFactor(0)`，每帧
`ts.tilePositionX = cam.scrollX * factor`——比创建 18000px 宽的巨图省内存得多。

### 3.2 素材要求（与 game-gen panorama 流程的差异点）

- 竞技场只要一张单屏构图全景图；横版**远景/中景层必须横向可无缝平铺**（seamless
  horizontally tileable）。生成 prompt 里明确加 `seamless horizontal tiling,
  left and right edges match perfectly`，并在处理脚本里做「左右边缘互换预览」验收。
- 快速起步的降级方案：单屏图镜像平铺（`REPEAT` + 偶数次翻转）当远景，先把滚动
  手感做出来，素材后补。
- 每个场景段一套层，段与段风格差异靠 §3.3 的过渡带衔接。

### 3.3 段间过渡带（"走出来的换景"）

**不做**竞技场式的原地 crossfade。在两段之间设 1~2 屏宽的**过渡带**，
用叙事性遮罩掩盖背景切换：

- 遮罩形态按题材选：黑暗甬道 / 浓雾隘口 / 隧道 / 夜幕——共同点是压暗 + 低对比，
  两侧背景在带内各自淡出/淡入，玩家察觉不到接缝。
- 过渡带内同步渐变三件事：**背景层纹理、粒子/招式调色板（PALETTE 按世界 x 分段取）、
  BGM crossfade**（竞技场的 `_playBGM` tween 逻辑直接搬）。
- 叙事卡（段名 + intro + hint）在**踏入新段时**弹出，替代竞技场的"开波弹卡"。

## 4. 关卡数据：距离驱动（levels.js schema）

时间轴换成空间轴。一条按 `at`（世界 x）升序的触发器数组：

```js
NS.SEGMENTS = [
  {
    name: '第一段 · …', intro: '…', hint: '…',
    x0: 0, x1: 3400,              // 段的世界区间（含过渡带起点）
    bgSet: 'seg1',                 // 该段的视差层纹理组
    bgm: 'music_seg1',
    palette: { ratio: 0, accent: null },
    triggers: [
      { at: 600,  type: 'grunt', dx: +620 },          // 玩家到 600 时，前方 620px 生成散兵
      { at: 1500, type: 'grunt', dx: +560 },
      { at: 1500, type: 'grunt', dx: -420 },          // 也可从身后出（dx 为负）
      { at: 2800, lock: {                              // 锁点：镜头锁单屏，清完解锁
          width: 960,
          waves: [                                     // 锁点内部 = 竞技场波次结构，原样复用
            { spawns: [ { t: 400, type: 'elite', dx: +500 }, … ] },
            { spawns: [ { t: 600, type: 'boss',  dx: +450 } ] },
          ],
      } },
    ],
  },
  …
];
```

要点：

- **触发一次即消费**（推进单向 + 棘轮，天然不会重复触发；若无棘轮需标记已触发）。
- 散兵触发**不锁镜头**：可打可绕，绕过且被甩开 >1.5 屏的散兵直接清理（§5）。
- **锁点**是竞技场逻辑的宿主：`_startWave/_checkWave/波间回血` 整套搬进来，
  外面只包一层「进锁 → 收 bounds → 跑波次 → 清完 → 解锁 + 前进提示（箭头/文字）」。
- 段末通常是锁点；最终段末锁点 = 终局 Boss，清完即 `_win()`。
- **胜利条件** = 推进到 `WORLD.W` 端点并清掉最终锁点（不再是"清完第 N 波"）。

## 5. 敌人生命周期（离屏管理）

竞技场里敌我永远同屏，横版必须补三条规则：

1. **休眠出生**：触发生成的敌人先 `dormant`，进入镜头右缘 +200px 内才激活 AI
   （复用竞技场「入场凝聚中 `alpha < 1` 不行动/不可击」的既有惯例做入场表现）。
2. **甩开清理**：非锁点敌人落后镜头左缘 >1.5 屏 → 直接销毁（不掉落、不计击杀）。
3. **投射物/地面效果出屏清理**：投射物离开镜头 ±0.5 屏销毁；减速带等地面效果
   保持世界坐标、到时自灭（本就有 dur）。

AI 本身几乎零改动：追踪/保距/读招全是「我的 x 与你的 x 的相对量」，坐标系变大天然兼容。
唯一注意：远程敌的 `keep` 保距逻辑要钳在镜头范围内，别把敌人保距保出屏外打隐身炮。

## 6. 契约与回归（bot / verify）

`__probe()` 在既有字段上**新增**（不改老字段）：

```js
progress: Math.round(P.x / NS.WORLD.W * 100),   // 推进百分比
segment: this.segIdx,                            // 当前段索引
locked: !!this.lock,                             // 是否在锁点战斗中
```

三档 bot 管线对应调整：

- **smart**（日常 playtest）：在竞技场策略之上加一条兜底——**视野内无活敌且不在锁点
  → 持续向右推进**。危险回避/风筝逻辑不变。
- **godmode**（必胜回归）：每 tick 秒杀 + 强制右移，验证「触发器全消费 → 每个锁点
  开/清/解 → 推进到终点 → win」全链路。断言 `progress` 单调不减。
- **dumb**（必败回归）：只朝最近敌人走，不放技能；若无敌人也向右走（否则会卡在
  空旷段永远遇不到敌人，gameover 路径走不到）。

verify 截图注意：`?autostart` 下要能截到**滚动中段**的画面（不只是出生点），
可加 `?warp=5000` 调试参数直接把玩家投放到指定世界 x。

## 8. 实施顺序（三阶段，每阶段末过 game-verify）

1. **骨架**：世界宽度 + 摄像机跟随 + 单层背景平铺（降级素材）+ 距离触发器 +
   每段末一个锁点 + bot 会推进。→ 此时玩法已经"是横版推进"了。
2. **观感**：视差分层、地面 chunk 化、过渡带（遮罩 + 调色板/BGM 空间渐变）、
   前景遮挡剪影、锁点解锁的前进提示。
3. **打磨**：棘轮细节、途中拾取节奏、正式可平铺素材逐段替换、`?warp` 调试参数、
   镜头手感（follow lerp / 锁点收放的 tween）。

## 9. 已知坑速查

- **忘了 scrollFactor(0)**：vignette/toast 被甩在出生点 → 装配时按 §2.3 表逐项过。
- **背景接缝**：非无缝素材直接 REPEAT 会闪竖线 → 镜像平铺过渡，或接缝处压暗景遮挡。
- **敌人保距出屏**：远程敌 keep 后退到镜头外 → keep 目标点钳到镜头内。
- **锁点内玩家出逃**：锁点必须同时钳玩家 x 和镜头 bounds，只钳一个会穿帮。
- **触发器重复消费**：无棘轮时玩家回走再前进会二次触发 → 触发即标记。
- **dumb bot 卡空旷段**：必败回归也要会向右走（§6）。
- **`tilePositionX` 用了负号**：视差方向反了，远景比前景跑得快 → 系数直接乘 scrollX，不取反。

## 10. 两游戏差异化设计原则（为什么值得并存）

> 若两个游戏只差一个滚动的摄像机，横版就沦为「ShadowForge 但你要走路去下一场架」，
> 比原版更差。**值得并存的理由，是两种骨架各自解锁一种不同的乐趣**：
> 竞技场解锁「决斗的深度」，横版解锁「旅途的广度」。真正要拉开的差异不在镜头，在下面。
> 做横版时最大的陷阱是不知不觉把竞技场的机制与数值照搬过来——本节就是防这一点。

### 10.1 结构性差异（格式逼出来的，没得选）

| 维度 | 竞技场（ShadowForge） | 横版推进 |
|---|---|---|
| 失败/重试颗粒度 | R 键从一屏重来，代价小 | 世界很长 → **必须检查点**，从头再来太暴躁 |
| 关卡编排媒介 | 波次「压力曲线」（2→4 敌人的尖峰） | 空间「拓扑」（高台远程、隘口炮塔、埋伏），搭地形而非调数值 |
| 敌人生命周期 | 敌我永远同屏 | 离屏管理（休眠出生/甩开清理，见 §5） |

### 10.2 设计性差异（主动创造，这才是并存的正当理由）

1. **签名机制必须分家（最重要）。** 竞技场的魂是「变形即武艺」——击败即吸收、
   化身为敌，只有在**被群敌包围、需挑选变成谁去克制谁**时才成立，天生属于竞技场。
   横版**不该原封继承**，否则两个游戏内核雷同。横版该有自己的动词，现成钩子是
   morph 引擎的**动量继承(drift)**：核心可以做成「攻击带动位移、招式与推进融为一体」的
   **动势格斗**，与竞技场「站定读招」正相反。

2. **战斗的深度 vs 广度。** 竞技场敌人是**决斗对手**（血厚、明确前摇、少量登场、
   逐个读招破解，奖励「精通」）；横版敌人是**移动的障碍**（血薄、成股涌来、威胁在走位
   与时机而非读招，奖励「流畅与压制」）。**同一套精灵图用相反的数值调**——切忌把竞技场
   的高血读招怪直接搬进横版，否则横版沦为一路打 Boss 的酷刑。

3. **生命与致死哲学。** 竞技场 = 「HP 消耗战 + 波间回血」，本质一场很长的架；
   横版 = **高致死 + 检查点**（一碰就死，或薄血+复活）。两种截然不同的紧张感。

4. **位移是一根支柱。** 竞技场只有地面走位（雾化闪避），地板平坦、唯一威胁是敌人；
   横版若无**跳跃/地形**就只是跑步机。深坑、高低差、隘口、塌陷地面——让**地形本身成为
   一个战斗单位**。这是横版最大块的全新内容，也是与竞技场最直观的距离。

5. **叙事载体反转。** 竞技场通过**对手**讲故事（具名敌人、一部图鉴）；横版通过
   **旅途与环境**讲故事（穿行过世界，环境自叙事）。ShadowForge「一层层下坠穿过五圈地狱」
   的题材其实**更适合横版**——竞技场反而要靠切背景硬讲。

6. **奖励回路。** 竞技场奖励精通（击杀/魄/无伤过波）；横版奖励**动势与压制**
   （不要停、连贯推进、速度/风格分），反过来强化第 1 条的动势核心。

### 10.3 一句话收束

**镜头是差异里最不重要的一环。** 竞技场往「决斗的深度」钻（读招、克制、精通方寸之地），
横版往「旅途的广度」铺（位移、地形、节奏张弛、动势格斗）。
每个都该**加倍下注自己的强项**，而非互相稀释成一个「带镜头的竞技场」。
