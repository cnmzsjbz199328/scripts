# 百变少女冒险记 (ShapeshifterGirl) — 开发文档

> 状态：**立项阶段**。本文档是项目唯一设计真源；素材生产提示词见同目录 `PROMPTS.md`。
> 架构铁律照 `game_runs/MIGRATION.md`，横版推进骨架照 `game_runs/SIDESCROLLER.md`，此处只写本作特有内容。

## 1. 一句话概念

**横版闯关**：少女小满拥有变身项链，必须在正确的时机变成正确的动物——猫翻高墙、鱼渡深水、鹰滑峡谷、熊破巨石——一路向东救回被魔雾掳走的弟弟。

- 题材骨架：**横版推进**（SIDESCROLLER.md 型），角色一路前进、摄像机跟随，Boss 战用锁点切竞技场。
- 即开即玩：START → 五关线性 → 通关，无存档/选关/星级（MIGRATION.md §0.5）。
- **初版设计决策：全部变身技能开局即拥有**。挑战来自「识别障碍 → 选对形态 → 操作过关」，不来自解锁。战力/资源限制（冷却、体力）留到后期调优（见 §6 史诗 E7）。

## 2. 核心机制：变身系统

### 2.1 形态一览

| 键 | 形态 | 移动特性 | 专属能力 | 克制的障碍/敌人 |
|---|---|---|---|---|
| `1` | 少女（人形） | 基准速度 + 单段跳 | 与 NPC/机关互动、推箱 | 无（安全默认态，通用通行） |
| `2` | 猫 🐱 | 快、跳高 1.6×、二段跳 | 攀上高台、钻矮缝（碰撞盒变矮） | 高墙、矮洞、需要精准平台跳的段落 |
| `3` | 鱼 🐟 | 仅水中可动，水中全向游动 | 潜水（人形入水即溺回岸） | 深水区、水下通道、水流 |
| `4` | 鹰 🦅 | 跳后按住↑滑翔（缓降+水平漂移） | 跨越宽峡谷、乘上升气流 | 宽壕沟、断崖、空中金币链 |
| `5` | 熊 🐻 | 慢、跳矮，但重量大 | 近战重击（击碎裂石/击退敌人）、免疫小怪冲撞 | 裂石墙、荆棘丛(踩过不掉血)、近战小怪 |

### 2.2 变身规则

- 任意时刻按 `1–5` 即时切换（`Q/E` 循环备用），变身瞬间由**代码做特效**（白闪 + 粒子 + 0.15s 顿帧），**不做变身动画帧**——省 AI 生成成本且节奏更爽快。
- 变身不打断水平动量；空中可变身（鹰接猫落地是高级技巧）。
- **错误形态不是死路而是弹回**：人形碰裂石=推不动、鱼上岸=原地扑腾 1s 后自动变回人形、非鱼入深水=呛水弹回岸边扣 1 心。软惩罚教学，不硬杀。
- 障碍带**形态提示图标**（首两关显示，后三关淡出）：设计上「读障碍猜形态」本身是乐趣，提示只做兜底。

### 2.3 战斗（轻量）

- 只有熊有主动攻击（重击，短前摇大硬直）；猫可踩头（马里奥式）；鹰俯冲可撞散飞行怪；鱼无战斗（水下怪靠绕行）。
- 敌人 3~4 种即可：巡逻小怪（熊击/猫踩）、投掷怪（鹰俯冲克制）、水下游弋怪（绕行）、Boss 魔雾兽（三阶段，每阶段弱点对应一种形态）。

## 3. 关卡设计（五关线性）

| 关 | 场景 | 教学重点 | 关键配置 |
|---|---|---|---|
| L1 林间小径 | 暖绿森林 | 人形移动/跳跃 + **猫**（高台、矮缝） | 无敌人，纯平台教学；结尾一面必须猫爬的高墙 |
| L2 月光溪谷 | 蓝夜溪流 | **鱼**（深水、水下通道）+ 猫复习 | 首个巡逻小怪（可绕）；水陆交替强制切换 |
| L3 风啸断崖 | 黄昏峡谷 | **鹰**（滑翔、上升气流）+ 投掷怪 | 宽壕沟连跳；坠落回最近落脚点扣 1 心，不重开 |
| L4 碎岩洞窟 | 暗紫洞穴 | **熊**（破裂石、抗荆棘、战斗）| 战斗密度最高；黑暗中形态图标改为轮廓发光 |
| L5 魔雾之巅 | 红黑云顶 | **混合**：全形态快切连段 | 推进段验收所有机制 → 锁点 Boss 三阶段（熊破甲→猫躲弹幕踩头→鹰俯冲终结） |

- 每关入口一张叙事卡（`__advanceCard()` 契约），讲弟弟留下的线索，5 张卡串出完整故事。
- 关卡数据全部进 `game/levels.js`（`window.SSG.LEVELS`），障碍用 `{ at: <推进距离>, type: 'gate', need: 'cat' }` 声明式描述——**加关卡不写代码**。

## 4. 技术栈要点

- **引擎**：Phaser 3（CDN 版，与全仓一致）+ `game_runs/_engine/`（hud / audio 必用；跨游戏复用代码只准进 `_engine`）。
- **加载**：按序 `<script>` + `window.SSG` 命名空间；**禁 ES module、禁 fetch json**。顺序：`_engine/*` → `config.js` → `levels.js` → `systems/*` → `render.js` → `scenes/*` → `main.js`。
- **场景**：`BootScene`（画底 + START 直接进 L1）+ `LevelScene`（每关 <250 行，数据驱动）。
- **对外契约**（playtest/verify 依赖，逐字不可破坏）：
  - `window.__probe()` 除标准字段外增加本作字段：`form`（当前形态）与 `nextGate: { at, need }`（最近障碍及其所需形态）——**让 playtest bot 能读出该变什么、在哪变**，这是本作 bot 可自动通关的前提。
  - `window.__gameState.player`、`window.__hudStart()`、`window.__advanceCard()`、`?autostart` / `navigator.webdriver` 跳菜单直进 L1。
- **素材分工**：
  - 少女 + 4 动物形态：`char-sprite` 管线（AI 绿幕网格 → 切割 → WebP 图集），清单与提示词见 `PROMPTS.md`。**AI 图必须走管线切割，禁手工切**。
  - 敌人：首选 `char-sprite` 同风格生成；若需要逐关节精控命中窗口的招式（Boss），该招式改走 `svg-sprite` 混轨，保持剪影/取景框一致。
  - 背景：远/中景剪影带走 WyrmsEnd 式绿幕抠像（提示词在 PROMPTS.md），天空/雾/光全部代码绘制；环境动效（草、萤火、水波）走 `svg-ambient`，产物拷进本目录。
- **验证门**（改玩法后按序必过）：
  1. `npx tsx skills/game-verify/verify.ts ShapeshifterGirl`
  2. `npx tsx skills/game-playtest/play.ts ShapeshifterGirl`
- **部署**：通关后录 10s `preview.mp4`（入库），注册进 `game_runs/games.json`（**注册放在游戏可玩之后**，避免 showreel 出现死链），Cloudflare Pages CI 自动发布。

## 6. 史诗与用户故事

### E1 项目脚手架（架构合规）
- **US-1.1** 作为开发者，我要按 MIGRATION.md 结构生成 `index.html + game/` 骨架（SSG 命名空间、按序 script、Boot→Level 双场景），使 verify 能截到「可玩画面」。
  - 验收：`verify.ts ShapeshifterGirl` 通过；`?autostart` 直进 L1；`__probe()` 返回合法字段。
- **US-1.2** 作为 playtest bot，我要 `__probe()` 暴露 `form` 与 `nextGate`，使我能在正确位置自动切换形态通关。
  - 验收：bot 脚本仅靠 probe 数据即可通过含 gate 的测试关。

### E2 素材生产与接入（char-sprite 管线）
- **US-2.1** 作为美术流程执行者，我要按 `PROMPTS.md` 完成 panorama → 5 张角色参考图 → 13 张动画网格图的生成与切割，产出 5 套 `spritesheet.webp + char.json`。
  - 验收：`assemble.ts` 全部通过；各行帧数=9、透明背景、剪影取景框一致。
- **US-2.2** 作为开发者，我要一个占位渲染层：素材缺失时画程序化剪影，`assets/sprites/` 有图则加载图集——两条路径共用同一动画状态机。
  - 验收：删掉 assets 目录游戏仍可完整通关。

### E3 变身系统核心
- **US-3.1** 作为玩家，我按 `1–5` 立即变身并看到白闪特效，水平动量保留，空中可变。
  - 验收：任意状态切换零报错；连续快切 20 次帧率无异常。
- **US-3.2** 作为玩家，每个形态有明确不同的移动手感（速度/跳高/碰撞盒/滑翔/游泳），见 §2.1 表。
  - 验收：数值全部来自 `config.js`（`SSG.Config.forms`），调参不改逻辑代码。
- **US-3.3** 作为玩家，用错形态得到软惩罚反馈（弹回/呛水/扑腾）而不是即死。
  - 验收：每种错误组合有专属反馈动画/音效；不产生软锁。

### E4 关卡、障碍与敌人
- **US-4.1** 作为关卡设计者，我在 `levels.js` 用声明式条目（gate/water/chasm/rock/enemy/updraft）拼出 §3 的五关，逻辑代码零改动。
- **US-4.2** 作为玩家，L1–L4 各专注教学一种形态、难度递进，L5 混合验收 + 三阶段 Boss。
  - 验收：playtest bot 全五关通关；单关时长 2–5 分钟，全程 10–30 分钟。
- **US-4.3** 作为玩家，每关开场看到叙事卡（弟弟的线索），Boss 战后看到团圆结局卡。

### E5 手感与精装修（照 MIGRATION.md §5 清单）

## 7. 风险与对策

| 风险 | 对策 |
|---|---|
| 5 套角色图集风格漂移 | 全部提示词锚定同一张 panorama + 统一 `{STYLE}` 串（见 PROMPTS.md §0）；剪影颜色与取景框一致是混轨/多形态的硬要求 |
| 形态切换导致碰撞盒突变卡进地形 | 变身时做「站立空间检测」，空间不足则拒绝变身并抖动提示（猫→熊在矮缝里必须失败） |
| bot 无法应对形态谜题 | `nextGate` 契约（US-1.2）从第一天就进 probe，playtest 脚本据此自动切形态 |
| 图未生成阻塞开发 | 占位渲染层（US-2.2）：无图可跑、有图即换 |
