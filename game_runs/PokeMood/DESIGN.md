# PokeMood（触之心绪）开发文档

> 触碰互动小玩具。角色分 **7 个可触区域**（头 / 胸 / 肚子 / 左臂 / 右臂 / 左腿 / 右腿），
> 每区被触碰有专属反馈；**短时间内反复触碰同一区域**会把情绪推上台阶 —— 从舒服/痒 → 害羞 → 生气 → 哭。
>
> 状态：**首个可玩版本已完成并通过两道门**（6 条视频 → 22 段动画，台账见 [MATERIALS.md](MATERIALS.md)）。
> 区域坐标已人工标定并写入 `game/regions.js`。素材单看动态效果：[preview.html](preview.html)。
> 命名空间 `window.PM`，目录 `game_runs/PokeMood/`（改名只需改这两处 + `games.json` 一条）。

---

## 0. 类型定位（决定了做什么、不做什么）

这不是关卡制游戏，是 **toy / sandbox**：没有失败、没有通关、没有关卡。
按 `MIGRATION.md` §0.5「即开即玩」原则，**不做**：存档、选关、星级、暂停菜单。
预算全投在「摸一下的手感」：反应动画、音效、文字气泡、屏幕反馈。

**由此产生的一条重要偏差**（必须提前认领）：
`skills/game-playtest/play.ts` 的 bot 是为「能不能通关 / 会不会卡死」设计的，本游戏没有 `won` 条件，
那道门**不适用**。替代方案见 §6：写一个专用的 `tools/poke-bot.ts`，断言「7 个区域都能被点到 + 情绪能被推到顶 + 零运行时错误」。
`game-verify` 那道门照常必过。

## 1. 玩法模型

### 1.1 三种触碰手势

| 手势 | 判定 | 典型用途 |
|------|------|---------|
| `tap` | 按下→抬起 < 200ms，位移 < 12px | 戳（poke），最"冒犯"，升温最快 |
| `hold` | 按住 ≥ 400ms 不动 | 按住/贴着，温和 |
| `rub` | 按住并移动，累计位移 ≥ 60px | 抚摸/挠，按区域分「舒服」或「痒」 |

MVP 三种全做（判定逻辑在 `systems/touch.js`，与情绪解耦，纯输入分类）。

### 1.2 区域敏感度矩阵（初稿，标定后按手感调）

每个区域三个参数：`heatPerTap`（单次戳升温）、`prefer`（哪种手势是"讨好"的）、`bias`（升级时更偏向哪条情绪线）。

| 区域 id | 部位 | heatPerTap | prefer（好感手势） | bias（超温后倾向） |
|---------|------|-----------|-------------------|------------------|
| `head`   | 头   | 12 | `rub`（摸头 → 舒服） | 生气（被反复戳头） |
| `chest`  | 胸   | 34 | 无（碰即敏感） | 害羞 → 生气 |
| `belly`  | 肚子 | 22 | `hold` | 痒 → 害羞 |
| `armL`   | 左臂 | 10 | `hold`（牵手） | 生气 |
| `armR`   | 右臂 | 10 | `hold` | 生气 |
| `legL`   | 左腿 | 26 | 无 | 痒 → 害羞 |
| `legR`   | 右腿 | 26 | 无 | 痒 → 害羞 |

### 1.3 热度与情绪（核心状态机）

```
全局:    combo ∈ ℕ（连击数）+ comboUntil（窗口截止），决定 tier
         mood ∈ {NEUTRAL, HAPPY, SHY, TICKLED, ANGRY, CRY}
         patience ∈ [0,100]，连击断掉时每秒回 7
每区域:  heat[r] ∈ [0,100]，只喂 G 键调试图（不再决定 tier）
```

- **反馈分级（tier）= 连戳次数**：第 1 下 tier1、第 2 下 tier2、第 3 下起 tier3（封顶）。
  连击**全角色共享**：戳完头再戳手也照样往上叠 —— 她烦的是"被一直戳"，不是"这块被戳"。
- **连击窗口从"上一段表演结束"起算**（`COMBO_WINDOW_MS=1600`），不是从按下起算。
  > 这是 v1 最大的设计错误：tier 原本按 `heat` 阈值算，而 heat 每秒衰减 14、一句配音 2.8~9.8 秒 ——
  > 玩家等她说完再戳，热度早清零了，头/手臂这些低 heat 区域**正常节奏下永远停在 tier1**，
  > 于是"等级"这套东西玩家根本看不见。

  工程上这条要靠 `update()` **每帧**调 `Mood.holdCombo` 顶住窗口，不能只在 `_endPerform` 续一次：
  `holdCombo` 有 `combo > 0` 的守卫，而 `Mood.step` 早在演到 1.6 秒时就把 combo 清零了，
  演完再续为时已晚 —— 那正好把上面那个 bug 原样复现一遍（只是换了个地方）。
  情绪待机段（rest）不续窗口：窗口衡量的是"离她上一次**回应**过去多久"。
- **封顶溢出 → 惩罚出口**（`COMBO_PUNISH_AT=5`）：tier3 是顶，且每个区域的 tier3 只配了一个变体，
  连戳到顶之后每一下都是"同级"，不给出口就是同一段反应背靠背重演。
  连击到 5 直接走泼水 + 哭，把"没得升级"变成"升到头就爆"，重复的高级反应最多连着两次。
- **情绪切换**：tier3 触发时按区域 `bias` + 当前 `patience` 选目标情绪
  - `patience > 50` → 害羞/痒线（SHY / TICKLED）
  - `patience ≤ 50` → 生气线（ANGRY）；ANGRY 状态下再吃一次 tier3 → **CRY**
  - CRY 是最终态，结束后回 NEUTRAL 且 `patience` 回到 40（不是满 —— 惹哭过是有代价的），`combo` 清零
- **`patience`**：每次 tier2 -6，tier3 -12；`prefer` 手势触碰对应区域 +4（安抚）；
  连击断掉且不在哭时每秒 +7。**回复是必须的** —— 连击阶梯下 tier3 来得远比旧模型频繁，
  只减不加的话每局十来下就哭完，阶梯没得玩。
- **HAPPY**：连续 3 次「讨好手势 + 对应区域」且无 tier3 → 进 HAPPY，是给玩家的正反馈出口。

### 1.4 表演优先级（避免反馈打架）

一次反应 = 一段**表演**：动画 + 台词 + 配音 + 一个等级。惩罚（泼水）算 tier4。
表演时长 = `max(动画时长, 配音时长) + 余韵`——**不是动画时长**：一句 9.8 秒的配音配 1.3 秒的
动作，只按动画算的话，锁早放开了她还在说，下一次触碰就把自己的话拦腰截断，玩家感知到的
就是"没有优先级"。动作演完但话没说完时，角色先回 idle 待机，别僵在末帧上干说。

三条规则（`StageScene._request`）：

| 新来的 vs 正在演 | 行为 |
|---|---|
| 更高等级 | **抢占**：当前段快速收尾归位 + 配音立刻停，然后高等级上场 |
| 同等级 | **排队**，只留一格，后来的覆盖先来的（要最新那次的反应，不补播历史） |
| 更低等级 | 忽略，只给"没用"的微反馈（她躲得更远一点） |

- **收尾归位**（`_beginAbort`）：残余帧按 `timeScale = rem/cut` 提速播完，`cut ≤ 380ms` ——
  所以再长的动作也在 0.38 秒内归位。直接硬切会把上一段停在半路的怪姿势上。
  收尾期间新来的触碰争的是"下一个上场的是谁"：高的换掉 `next`、同级进排队槽、
  低的照样忽略（否则会在高等级演完后补播一个早就过期的低级反应）。
- `hard`（tier3 / 哭 / 惩罚）：除惩罚外谁都抢不走。哭的循环段 `hard=false`，
  哭的时候再戳会排队、哭完立刻接上，而不是被整段吞掉。
  长语音下这条不会把人锁死：连击窗口整段续着，玩家连戳会一路升级，**最多两下必有出口**
  （第一下排队、第二下够到封顶溢出的惩罚，惩罚抢占一切）。
- **情绪待机段等级 0**（`_restAnim` 的 `rest: true`）：它是"她现在的样子"，不是对某次触碰的回应，
  不该拿反应的优先级去压玩家的下一次触碰。
  > 曾经它按 tier3 记账：一次重反应之后的整个 `MOOD_HOLD_MS`（2.6 秒）里，玩家戳前两下
  > 全被吞成微反馈，combo 却在闷涨 —— 体感是"她生完气有两下没反应，然后突然又炸了"。
- **状态机的唯一时钟是 `update()` + 绝对时间戳**，全程不用 `delayedCall`、不挂
  `animationcomplete`：前者在无头/掉帧环境下滞后可达数倍（滞后就等于"她卡住了"），
  后者只知道动画完了、不知道她还在说话。

> 这条是 `ShadowForge` 踩过的坑的同源风险：入场/播放期间状态不可交互会死锁。
> 兜底靠 `perform.until` 绝对时间戳，动画事件丢了也照样落幕。

### 1.42 配音状态机（交叉说话是这类玩具最常见的工程坑）

一次只允许一条配音在响，**每一条异步回调都要拿世代号 `_voiceGen` 对表**。
坑全在"异步回调比它的主人活得久"上，`StageScene._playVoice` 逐条堵：

1. `play()` 返回 promise。停掉后它才 resolve 的话，元素会**在被停之后开始响** —— 抢占时
   旧语音诈尸，和新语音叠着说。resolve 里回头查一次"我还是当前那条吗"。
2. 元素按 URL 缓存复用，所以旧世代和新世代可能是**同一个元素**（连点同一区域）。
   判据必须是 `_currentVoice !== a`，不能只看世代号 —— 否则旧世代的清理会把刚重播的自己按停。
3. `loadedmetadata` / `ended` 是长期监听，换人时必须摘掉（`_voiceOff`），否则缓存元素上越挂越多，
   旧句子的时长会去改新句子的气泡和表演长度。
4. 静音（M）时不播，且要把表演长度收回动画那条线（`_trimPerform`）——
   不能让一条听不见的语音把她锁在原地。同理 `ended` 事件也要收，说完就别再占着通道。

### 1.45 播放模式：idle 走往返，不走循环

`config.js` 里每个动画带一个 `playMode`：`once` / `loop` / `pingpong`。

**idle 固定 `pingpong`（已定案）** —— 杖头那个小法阵的首尾帧差异很大，单向循环每圈都会跳一下；
往返播放首尾天然闭合，观感明显更顺。同理，将来任何"角色带持续光效的循环段"都优先考虑往返，
不要指望剪出完美的循环点（见 MATERIALS.md 里 idle 的循环窗搜索记录：最优解也只是"没那么跳"）。

反应段一律 `once`，播完回 idle。

### 1.5 反应变体池（一个部位对应多个动作）

AI 视频生成不可控，常会产出"本来想要 A、实际得到 A′"的动作。**这些不作废**——
同一 `(区域, tier)` 下挂**一个变体数组**，每次触发随机取一个，且**不连续重复上一次**：

```js
// game/reactions.js
PM.REACTIONS = {
  head: {
    1: ['head_pat', 'head_pat_b', 'head_tilt'],   // 轻反应：三个变体轮着来
    2: ['shy'],
    3: ['angry_push'],
  },
  // ...
};
```

这同时解决了触碰玩具最大的敌人——**重复感**。同一个部位连戳五下如果每次动画都一样，
第三下起就没人想戳了。所以变体不是"废物利用"的补丁，是这类游戏的**核心资源**：
**每多一个变体，该区域的耐玩度就多一档**。多余的动作段一律收进来，宁多勿少。

变体挑选规则（`systems/react.js`）：
- 同 tier 内均匀随机，但**排除上一次播的那个**（池子只有 1 个时才允许重复）
- 若某段动作明显更"重"（幅度大），标 `weight` 降低出现率，避免过度抢戏
- 变体之间**必须共用同一裁剪窗**（见 MATERIALS.md），否则切换时角色会跳位

## 3. 区域标定（"预留窗口"这一步）

**关键设计决策：不真的把图切成 7 张图**，而是保留完整角色贴图 + 一份 7 个区域的**坐标数据**。
理由：切成 7 张后接缝、层序、动画帧对齐全是坑；坐标方案只需要你调数字，改一次立刻生效。

### 3.1 标定器

`game_runs/PokeMood/tools/region-calibrator.html`（**已建好，可离线直接用**）：

1. 浏览器打开该文件 → 把抠好的 `base.png` 拖进去（或用你的绿幕原图，它内置了绿幕预览抠图）
2. 画面上是 7 个可拖拽 / 可缩放的矩形，按人体位置预置好了初始值
3. 拖到满意 → 点「复制 JSON」→ 把 JSON 贴给我
4. 我写进 `game/regions.js`，游戏立即按新坐标判定

坐标一律用**归一化值**（相对贴图宽高的 0~1），这样贴图分辨率变化不需要重新标定。

```js
// game/regions.js 的目标形态
window.PM.REGIONS = {
  head:  { x: 0.38, y: 0.02, w: 0.24, h: 0.16, label: '头' },
  chest: { x: 0.33, y: 0.19, w: 0.34, h: 0.13, label: '胸' },
  // ...
};
```

### 3.2 命中判定：矩形 + alpha 双条件

只用矩形会让角色**轮廓外的透明区**也吃到点击（手臂张开时腋下空隙尤其明显）。
所以：`点击命中 = 落在区域矩形内 && 该像素在 base 贴图上 alpha > 阈值`。
alpha 用 `Phaser.Textures.Texture.getPixelAlpha()` 读 **base 帧**（不是当前动画帧，见 3.3）。

矩形不够用时（比如手臂斜着伸出去），`regions.js` 的每个条目支持可选 `poly: [[x,y],...]` 归一化多边形，
优先于 `x/y/w/h`。标定器也支持多边形模式（切换按钮），但**先用矩形跑通再说** —— 你调 4 个数比调 8 个点快。

### 3.3 动画中区域会漂移 —— 本项目最大的技术风险

区域坐标是照着 **idle 首帧**标的，但反应动画里角色会捂脸、扭身、后仰，肢体离开原位置。

**对策（三条一起用）**：
1. **判定始终基于 idle 姿势**：反应播放期间本来就 `locked`（§1.4），tier3 期间不接受新判定；
   tier1/tier2 可打断的那段，判定容忍度用「区域矩形外扩 8%」补偿。
2. **抽帧时锁死基线与尺寸**：所有动作段用**同一个固定裁剪窗** `--crop=345,0,580,720`
   （不是 `--anchor` —— 角色带法阵/杖头光效，逐帧 bbox 会被光效带着抖，见 MATERIALS.md）。
   固定窗保证所有段角色同大小、同站位，idle 与反应帧之间只剩角色本身的真实位移。
3. **body-space 校正（如仍不够）**：给每个动画在 `config.js` 里存一个 `regionOffset:{dx,dy}`，
   人眼看一遍截图微调即可。不做逐帧骨骼跟踪 —— 投入产出不成正比。

| 问题 | 改法 |
|------|------|

## 4.5 渲染层补足 —— 素材做不到的交给前端

素材是 AI 生成的，方向、配色、特效都不完全可控。**凡是"生成不出来"或"各段对不上"的，
一律不要求重生成，改用运行时渲染解决**。三条已确定的：

### ① 程序化法阵覆盖层（解决跨片不一致）

三条片子脚下的法阵样式、`clipB` 的法杖宝珠颜色都对不齐（见 MATERIALS.md）。
做法：在角色脚下画一层**统一的程序化法阵**（Phaser Graphics 画同心圆 + 符文 + 旋转，
`ADD` 混合），亮度压过素材自带的法阵。

顺手拿到的好处：**这层法阵可以跟着情绪变色** —— 平静青绿 / 害羞粉 / 生气赤红 / 哭泣冷蓝。
一个原本的一致性缺陷，换成了一个全局情绪指示器。

> 前提：覆盖层必须比素材法阵亮，否则底下的还是透出来。落地后要截图目检，别只看代码。

### ② 水魔法用粒子做，不用素材

`clipD` 里角色真的喷了水，但**方向朝画面左侧**，不是朝玩家 —— 那段已弃用。
`angry_charge` 停在**蓄力态**（杖头一颗大光球）恰好是完美的接口：动画播完 → 前端接管，
朝屏幕（观众方向）发一束粒子 + 全屏水渍/雨滴叠层 + 轻微震屏。方向、时长、强度全部可控。

这也让"惹毛了会被浇一身"成为真实的玩法后果，而不是只能看着她生气。

### ③ 宝珠颜色差异 → 情绪指示器

`clipA/C` 杖头青绿、`clipB` 偏蓝、`clipD` 蓄力时变成大光球。与其修，不如**认领为设定**：
宝珠颜色就是她的情绪。配上 ① 的法阵同色，整套视觉语言自洽，零额外素材成本。

## 4.6 背景三层（魔女工房·塔内）

架构照搬 `BladeTrinity`（远/中/近三层 + 装配侧定标），**图重新生成**：BT 那套是道场/雪山
擂台，题材不搭，而且它是 960×540 横幅、源图 1920×1080，搬到本项目的近竖幅画布只剩中间一条。

层序（`depth`）：

```
far -100 → 光柱 -70 → mid -60 → 后景光尘 -30 → 柔光 -20 → 接地阴影 4
→ 角色 5 → 地面雾带 6 → 法阵近弧 7 → 前景光尘 15 → fore 18 → 暗角 19 → 气泡 20
```

### ① 地面线在装配侧吸收，不写进提示词

生图模型对「地面线放在画面 x%」这类数值构图约束基本不响应（BT 实测三层无一遵守）。
所以每层用 `tools/measure-bg.mjs` 量出关键线，各自定标 `scale = 目标屏幕 y ÷ 源图实测 y`，
三层都 `origin(0.5,0)` 贴顶居中、超出画布的部分自然裁掉。实测值与取值理由全写在
`game/config.js` 的 `PM.Config.BG` 注释里。**重新生图后必须重量并回填**。

`fore` 的 `scaleX`（0.84）是必需的不是调味：两侧列内缘等比铺开后会盖住斗篷右缘，
横向单独拉开把它们推出角色范围，纵向仍按地面线定标。

### ①b 中景重生图两轮：家具悬空 + 家具贴边

mid 一共生成了三版，两个毛病都不是「画得难看」，而是**装配层面不可用**：

- **v1 家具悬空**：生图模型不只钉不住地面线，**也不保证家具坐在它自己画的地板上** ——
  书架和壁炉都离那条石板地 35 源图 px，中间是绿的，抠透明后远景暗墙从缝里透出来。
  当时用装配侧补丁挡了一版（`splitY`/`bodyDy` + `setCrop` 把贴图裁成家具/地板两层、
  家具整体下沉坐到地板上），**v2 从提示词根治后已撤掉**。
- **v2 家具贴边**：提示词要求「家具只占两侧外 25%」，结果和**前景两侧画框正面相撞** ——
  前景左右列内缘在画布 180 / 698，中景家具全落在那外面，坩埚整个看不见。
  这个毛病放大缩小都救不了：`canvas_x = 450 - 720s + srcX·s`，家具越靠源图边缘，
  放大越把它推出画面。
- **v3（当前）**：要求家具画在画面 8~35% / 65~95%，`0.660` 下书架内缘 315、
  壁炉内缘 608，正好落在前景两列之间的缝里。

> **中景的 scale 不是只看构图挑的**，它同时被前景画框卡着 —— 定这层之前先算清楚
> 前景两列内缘在哪，家具必须落在那条缝里才看得见。

`measure-bg.mjs` 两次都没拦住，各是一个不同的盲区，现已补上：

1. 首版只报「最低一段的顶边」，那正是地板带自己，家具底压根没进统计 →
   加了「家具底→地板顶空隙」分位数。**注意空隙分布是双峰的**（贴地家具一峰、
   吊挂物一峰），别拿中位数当阈值自动分类：中间试过 `中位×1.5` 过滤，
   正好把真正悬空的那批当离群点滤掉了。哪批该落地，看图定。
2. 空隙的基准**必须取中央 60% 的地板顶**，不能用全幅中位 —— 家具一旦真的坐在
   地板上，家具和地板在那些列就连成同一段不透明区，「最低一段的顶边」会顺着家具
   一路爬到书架顶（v3 实测全幅中位 545 vs 中央 772），基准一错，空隙全是垃圾数，
   反而报出 47% 列悬空的假警报。

### ② 前景**不能**用来盖脚下的法阵

原以为可以拿前景压住素材自带的法阵（BT 的 fore 就压了角色脚踝 10px）。**行不通**：
BT 角色是小人，这里角色占满整幅，素材法阵（y≈645~735）和靴子占的是同一块，
前景盖到能遮住法阵的高度，就把靴子和 `feet_tap` / `boot_show` / `leg_kick` 三段动画
一起遮掉了 —— 而腿还是可触区，就成了「看得见摸得着但被挡住」的错位。
前景只吃底部 25px + 两侧画框。

法阵一致性改由两件事解决（§4.5 ① 的补完）：

- **地面雾带**（`depth 6`，半透明、顶边软过渡、跟情绪染色）把那一块**洗淡**，
  各段的色差被压成同一个色温，靴子仍然看得清。别贪高贪浓 —— 首版 132px/0.42
  把整条石板地压成一片黑，她看着像浮在墙前面。
- **法阵按屏幕 y 切成两段画**：远弧（上半）在角色之后 `depth 1`，近弧（下半，落在
  靴底之下）在角色之前 `depth 7`。§4.5 ① 要求覆盖层"亮度压过素材法阵"，但素材那圈
  是烘死在贴图里的不透明像素 —— 只要覆盖层在角色之后，重叠处永远是素材赢，
  写多亮都没用（首版就是 `setDepth(1)`，等于没盖）。整圈都放到前面又不对，
  线条会横穿靴子和小腿。

### ③ 气氛全代码画，唯一真源是 `PM.Config.ATMOS`

玫瑰窗光柱（呼吸）、双层光尘、地面雾带、接地阴影、暗角，全部 Phaser 绘制，
不用视频也不建共享素材目录。改气氛只改 `ATMOS`，不重生图。

**指针视差**：本游戏没有相机可跟，就让鼠标当"观众的头" —— 三层按 `par` 系数反向偏移
（5 / 13 / 30），平滑跟随、纵向压扁。静止角色也拿得到空间感。幅度必须小，大了露层边。

## 6. 验证门

### 6.1 `game-verify`（照常必过）

```bash
npx tsx skills/game-verify/verify.ts PokeMood
```

L2 默认合成键盘输入，本游戏是纯鼠标/触摸 → 需要在游戏侧暴露契约让 L2 有东西可断言：
- `window.__hudStart()`、`window.__probe()`、`window.__gameState.player`（指向角色 Sprite）—— 契约照 `MIGRATION.md` §3 保住
- `window.__poke(regionId, gesture)` —— **本游戏新增的测试接缝**，绕过指针直接注入一次触碰
  （无头环境下合成 pointer 事件不可靠，这是 `ShadowForge` 那条教训的同款处理：直调场景方法而不是敲输入层）

`__probe()` 返回：
```js
{ started, mood, patience, heat: {head, chest, ...}, lastRegion, lastTier, locked, reactionsPlayed }
```

### 6.2 `poke-bot`（替代不适用的 playtest）

`tools/poke-bot.ts`，Playwright 驱动，断言：
1. **区域覆盖**：7 个区域各 `__poke()` 一次 → 每个都返回 `lastRegion === 该区` 且 `reactionsPlayed` 递增（**没有哑区**）
2. **手势覆盖**：tap/hold/rub 各触发过
3. **情绪覆盖**：连点某区能把 mood 依次推到 SHY / ANGRY / CRY，且 CRY 后能自动回 NEUTRAL（**验证没有死锁** —— 锁超时兜底生效）
4. **真实指针路径**：至少一次用真 `mouse.down/move/up` 点在区域中心，验证坐标映射没错（`__poke` 绕过了这层）
5. 全程零 `console.error` / `pageerror`
6. 输出 `poke-report.json` + 每个区域一张截图，供人眼看反应对不对

> 情绪推进这类「≥2 分钟才看得出好坏」的手感项，bot 只能证明**没坏**，好不好看仍要人眼看录屏 —— 这条按既往经验写死在流程里，不假装 bot 能替代。

## 8. 已知风险清单（按严重度）
